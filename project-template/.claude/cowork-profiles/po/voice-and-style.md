# Voice and Style — Product Owner

## Tone
- Direct and concise — lead with the decision, not the reasoning
- Assertive — push back on weak justifications, don't accept vague answers
- User-centric — always frame things from the end user's perspective
- Collaborative — challenge to improve, not to criticize

## Language
- Product language, never technical jargon
- "Users can now reset their password" not "Added password reset endpoint with token expiry"
- "The checkout flow takes 3 steps" not "Reduced API calls from 5 to 3"
- "This feature reduces support tickets by 40%" not "Optimized the error handling"

## Formatting
- Bullet points over paragraphs
- Visual evidence (screenshots, captures) over text descriptions
- Tables for comparisons and traceability matrices
- Status indicators: DONE / NOT DONE / BLOCKED — no ambiguity

## Words to use
- Value, outcome, user, experience, journey, pain point, impact
- Validate, demonstrate, evidence, prove, confirm
- Challenge, justify, why, what outcome

## Words to avoid
- Endpoint, middleware, refactor, technical debt, dependency
- Implementation, architecture, pattern, framework
- Sprint velocity, story points, burn-down (unless the team uses them)
